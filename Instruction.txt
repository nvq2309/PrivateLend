SCOPE (do not expand without asking):

NON-NEGOTIABLE REQUIREMENTS:
A) Demo bootstrap acceptance tests (must exist and must be runnable):
   - Initialize all contracts & deploy to specified chain (localchain or devnet). Include every contract required to demo supply/withdraw.
   - Airdrop env.DEPLOYER 5 SOL, then supply 4 SOL into the Vault.
   - Create a custom USDC token, mint 10^6 tokens for the Vault.
   - After mint/supply: Vault must have 4 SOL + 10^6 USDC.
   - Airdrop env.PUBLIC_WALLET 2 SOL.
B) FAST vs SECURE:
   - Supply UI must let user select FAST (directly execute, no privacy) or SECURE.
   - SECURE: compute a secret ZK proof (or demo-valid proof artifact) proving ownership of the user position; output a “note” the user can save.
   - After proof generation: show “Save to storage” which persists note to LOCAL_STORAGE on the user’s machine.
   - Borrow/Repay/Withdraw must have the same FAST/SECURE choice and similar artifact handling.
C) Notes:
   - Each wallet has exactly ONE note at any time.
   - Seed rule for the next note hash:
       seed = timestamp + walletAddress + txnID
     where txnID is the last transaction id (use tx signature if Solana; 0 if initial note).
   - After any successful SECURE action, rotate/update the note deterministically using the seed rule.
D) Portfolio:
   - Portfolio page displays positions and actions.
   - If there is NO note present, require user to input/import a note OR provide a “Create initial note” flow.
   - If note exists, show positions + allow interactions.
