PHASE 3: PRIVACY LAYER (Stealth Addresses + Arcium)
---------------------------------------------------
The privacy layer implements TRUE on-chain privacy using a mixer-style approach with Arcium integration:

3.1 STEALTH ADDRESS GENERATION
   - Generate one-time stealth addresses for deposits
   - User's deposit goes to a stealth address, not their main wallet
   - Stealth address is derived from: user_secret + vault_pubkey + nonce
   - Only the user (with their secret) can prove ownership

3.2 ARCIUM INTEGRATION FOR ENCRYPTED BALANCES
   - Use @arcium-hq/client for encrypted balance storage
   - Balances stored as ciphertext on-chain (already partially implemented in veillend.ts)
   - Client-side decryption with user's Arcium keypair

3.3 NOTE SYSTEM WITH COMMITMENT SCHEME
   - Upgrade note system to use Pedersen commitments
   - Note contains: commitment to (balance, nullifier)
   - Withdrawal requires proof of commitment without revealing balance

3.4 ZK PROOF GENERATION
   - Implement actual ZK proofs (or verifiable demo proofs)
   - Prove: "I own a note with value >= X" without revealing identity
   - Use nullifiers to prevent double-spend

Privacy Flow:
  DEPOSIT (SECURE mode):
    1. Generate stealth address from user secret
    2. User sends funds to stealth address
    3. Create encrypted commitment using Arcium
    4. Generate note with commitment hash
    5. User saves note locally (only they can spend)

  WITHDRAW (SECURE mode):
    1. User provides note
    2. Generate ZK proof of note ownership
    3. Submit proof + nullifier to contract
    4. Funds sent to user's chosen address
    5. Old note invalidated, new note generated
